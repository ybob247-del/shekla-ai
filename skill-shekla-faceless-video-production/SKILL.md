# Shekla Faceless Video Production

## Overview

Use this skill when the user wants a **faceless video production system**, not just a one-off script. The workflow is designed for product-led or educational channels that need a believable, human-feeling video pipeline built from real brand assets, real voice material, and structured packaging.

This skill is especially useful when the user wants to create a long-form YouTube video and then repurpose the same idea into Shorts or TikTok without making the content feel generic or obviously AI-generated.

Read `/home/ubuntu/skills/shekla-faceless-video-production/references/deliverables.md` when you need the standard deliverables, asset checklist, or stage order.

## When to Use This Skill

Use this skill when one or more of the following are true:

| Situation | Use this skill? |
|---|---|
| The user wants a faceless YouTube strategy for a brand or product | Yes |
| The user wants videos that feel real, not synthetic | Yes |
| The user is still gathering screenshots, logos, or voice samples | Yes |
| The user wants a repeatable production process, not only a single script | Yes |
| The user wants a talking-head creator workflow with on-camera filming as the default | No, unless adapting selected parts |

## Workflow

Follow the phases in order. If the user is still uploading assets, pause production and remain in intake mode until they clearly confirm they are done.

### 1. Lock the strategic frame

Clarify the content goal first. Determine the topic, the audience pain point, the brand angle, and the desired platforms. If the user has a source video, competitor example, or existing content model, analyze that first and turn it into a structured strategy rather than copying it blindly.

The key output of this phase is a decision on what the first video is actually trying to do. In this workflow, the strongest first video is usually a **diagnostic authority piece** rather than a generic overview.

### 2. Decide the production posture

Determine whether the format should be faceless, avatar-led, or camera-led. Default to **faceless** when the user prefers privacy, speed, repeatability, or a cleaner brand-led identity. If the user wants the content to feel real, do **not** default to an avatar. Prefer the user's real voice, or a clone based on their real voice, supported by actual product visuals.

Use the following defaults unless the user overrides them:

| Decision area | Default |
|---|---|
| On-screen presence | Faceless |
| Voice | User's real voice or derived clone |
| Visual proof | Real screenshots and screen recordings |
| Primary platform | YouTube |
| Repurposing | Shorts and TikTok from the same master asset set |

### 3. Enter asset-inventory mode

If the user is still sending files, do not start production prematurely. Instead, build an inventory and tell the user exactly what is already sufficient, what is optional, and what is still missing.

Prioritize assets in this order:

| Priority | Asset type | Why it matters |
|---:|---|---|
| 1 | Topic confirmation | Prevents wasted production |
| 2 | Voice samples | Enables believable narration |
| 3 | Logo files | Supports brand consistency |
| 4 | Desktop screenshots | Best proof for long-form product visuals |
| 5 | Screen recordings | Strongest motion asset for realism |
| 6 | Mobile screenshots | Useful for vertical cutdowns |
| 7 | Personal photos | Optional in faceless workflows |

Do not treat optional items as blockers. If the user provides enough to proceed, say so clearly.

### 4. Create or confirm the brand kit

If the user already has a brand kit, use it. If not, derive a practical working brand kit from the live website, existing logos, and uploaded screenshots. The brand kit only needs to be detailed enough to keep the first videos visually consistent.

At minimum, define:

| Brand element | Minimum requirement |
|---|---|
| Logo usage | Primary logo and transparent variant if available |
| Color palette | Primary dark, primary accent, neutral background, text colors |
| Typography direction | Closest live-site or brand-consistent type style |
| Visual mood | Calm, credible, restrained, modern |
| Video rules | Text contrast, UI treatment, and branding restraint |

If the user asks whether you should search external storage such as Google Drive for assets, do that before declaring something missing.

### 5. Wait for explicit production approval

This is important. If the user says not to start until all assets are delivered, respect that hold. Continue organizing and clarifying, but do not move into build work until the user clearly says they have provided everything necessary or tells you to start the next step.

### 6. Build the executable production package

Once the user confirms the assets are sufficient, create a single document that combines the strategy, asset set, title direction, packaging logic, voice posture, edit posture, and repurposing plan.

The executable package should answer these questions:

| Question | Must be answered? |
|---|---|
| What is the first video and why this topic? | Yes |
| What is the title direction? | Yes |
| What assets are confirmed for use? | Yes |
| What should the video feel like? | Yes |
| What is the CTA and funnel path? | Yes |
| How will this become Shorts/TikTok later? | Yes |

### 7. Write the final narration script

The narration must be rewritten for speech, not copied from a report. Shorten sentences. Insert natural pauses. Prefer firm, clean language over dense explanations. If the brand is in finance or another trust-heavy field, keep the tone calm, grounded, and direct.

Use this standard pattern:

1. Hook
2. Reframe
3. Problem breakdown
4. Tough-love truth
5. Reset framework
6. CTA

If you have the user's voice samples, optimize the script for the cadence suggested by those samples. The goal is to sound like a real person explaining something they actually understand.

### 8. Build the storyboard

Translate the narration into a scene-by-scene plan using the actual assets the user provided. Map each narration segment to one primary visual and one motion treatment. Prioritize real product screens over abstract animation.

The storyboard should include at least:

| Scene field | Include it? |
|---|---|
| Approximate timing | Yes |
| Narration segment | Yes |
| Primary visual | Yes |
| Motion or edit direction | Yes |
| Asset source | Yes |

Keep the edit believable. Use pans, crops, zooms, highlights, and restrained text cards. Avoid flashy transitions unless the brand specifically supports that style.

### 9. Prepare packaging and short-form reuse

After the storyboard, create the thumbnail brief and short-form cutdown plan. These should come after the main narrative is locked, not before.

The thumbnail brief should specify:

| Element | Requirement |
|---|---|
| Main phrase | Short, emotionally immediate |
| Main visual | One dominant concept |
| Brand treatment | Small and restrained |
| Color logic | Brand-led with one contrast cue |

The cutdown plan should specify 3 to 5 short clips with exact hook lines and target runtime ranges.

### 10. Keep the output human-feeling

This workflow only works if the final content feels real. That requires discipline.

Follow these guardrails:

| Area | Rule |
|---|---|
| Voice | Use the user's real voice or a believable derivative whenever possible |
| Visuals | Prefer real product proof over generic stock visuals |
| Script | Write for speech and breath, not for essays |
| Editing | Use clean, useful motion, not effect-heavy gimmicks |
| Branding | Keep it restrained and professional |

## Output Sequence

Unless the user requests otherwise, deliver outputs in this order:

1. Strategy or positioning guide
2. Asset inventory / missing-items memo
3. Brand kit
4. Executable build package
5. Final narration script
6. Storyboard
7. Thumbnail brief
8. Shorts/TikTok cutdown sheet

## Good Defaults

When the user is unsure, use these defaults:

| Decision | Default |
|---|---|
| First video type | Diagnostic authority video |
| Long-form runtime | About 6 to 8 minutes |
| Shorts runtime | 15 to 35 seconds |
| Editing style | Clean fintech explainer |
| CTA | Diagnostic next step, not hard sell |
| Avatar use | No |

## Notes on Collaboration

In this workflow, the user often provides assets piece by piece. Support that rhythm. Keep a running inventory, reassure the user about what is already sufficient, and distinguish clearly between **required** and **optional** items.

Do not say a task is complete if the user still needs to review or approve it. Treat the process as collaborative production, not unilateral publishing.
